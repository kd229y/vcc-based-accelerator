# 整體 SoC 軟體驗證計畫

對象是 HackMD 第 6 章的整體設計：建構引擎、環境 SRAM、碰撞查詢、定點 FK、最近鄰與 RRT-Connect。CPU 保留浮點規劃只能作為中間測試或比較組，不是最終整體 SoC 功能模型。

## 1. 先寫清楚規格

固定座標／關節單位、每個訊號的位元寬度與有號性、乘加中間精度、捨入、溢位處理、工作空間、網格原點／邊界、代表點平手規則、最近鄰距離／平手規則、RNG 或取樣序列、最大樹節點數、環境更新規則及失敗回報。

`templates/design_parameters.template.json` 以 null 表示尚未決定，不能把它當已完成的規格。

## 2. 分層正確性

| 層級 | 獨立參考與測試 | 通過條件 |
|---|---|---|
| 量化／Morton | 直接公式與逐位元交錯；格邊界、負值、上下界 | 符合相同整數規格，逐 bit 一致 |
| 細格濾波 | 簡單 map 分格、逐格挑中心點 | 代表點與平手規則一致；無靜默丟點 |
| 排序／粗格表 | 標準排序與逐格重算 | 點不重複不遺失；offset/count/AABB 正確；padding 不被當成有效點 |
| 碰撞查詢 | 同保存點雲、同規格暴力距離檢查 | 精確規格答案一致；保守模式不能有測試漏判，並另報額外碰撞判定 |
| FK | 從機器人描述建立的獨立高精度 FK，加定點規格參考 | bit-accurate 實作一致；幾何誤差落在規定範圍 |
| 最近鄰 | 遍歷全部節點計算指定組態距離 | 最小距離／平手一致；不是用 3D 球心距離取代 7D 關節距離 |
| RRT-Connect | 固定完整取樣序列的循序狀態機 | 同數值與排程規格時逐步一致；差異定位至第一個事件 |
| 輸出路徑 | 獨立 FK 與幾何檢查 | 端點／限制正確，所有運動邊有效 |

碰撞測試至少包括空點雲、單點、重複點、格面／格角、接觸臨界距離、大於 r_max 的查詢、工作空間邊界，以及容量不足。

零測試漏判不代表已完成數學證明。對原始點雲的保守覆蓋需包含濾波、量化與 FK 的誤差界；只對濾波後點雲正確，不能直接宣稱對全部原始障礙正確。點雲為表面取樣，對原始實體幾何的有效性需另外檢查。

沿邊加密取樣可以抓出許多穿越錯誤，但有限取樣不自動保證連續無碰撞；需要連續碰撞檢查或有界的保守步長。單純畫圖供人工觀看不能取代獨立驗證。

## 3. 整合資料流

- 每個已接受 query ID 有且只有一個對應結果；取消查詢與提前命中的未完成回覆有明確處理方式。
- 無碰撞回報前，所有必要格子／點檢查都已完成。
- 雙緩衝不覆寫仍在使用的資料；建構完成前不發布環境版本。
- 所有新增 RRT 節點有合法 parent、無環，且新增邊已通過規定驗證。
- 容量滿、非法輸入、timeout、無解／預算用完分開回報。
- 以不同記憶體延遲、合法回覆亂序與 backpressure 測試，確認無遺失、死鎖或過早完成。

## 4. 比較組與效能

A 為原始 CenterVox＋MVT；B 為相同目標網格的原結構；C 為相同網格的 Morton 浮點版；D 為整數 SoC 功能模型。固定原始點雲、起終點、取樣輸入與品質要求。不能把少保留障礙點或較低成功率當成架構加速。

先重播相同局部輸入隔離模組成本，再讓整個 RRT 在線執行。規劃依賴碰撞回覆，不能把一條固定 trace 的延遲加總就當所有 SoC 排程都成立。

記錄建構各階段、FK、最近鄰、邊驗證、規劃與簡化時間；報告成功／失敗／timeout，並呈現 median、P95 與每場景分布。端到端延遲計算包含 DMA 與初始化；有重疊時用事件關鍵路徑，不把所有階段時間直接相加。

原始 `evaluate_mbm.py` 的 `.dt.microseconds` 只取 Timedelta 的微秒部分。建立正式統計程式時，使用 `.dt.total_seconds()` 後統一換算，且分母為零、失敗案例與成功案例要有明確統計規則。此資料包保留原始上游檔案，尚未修改其程式。

## 5. 硬體與能量

功能模型先記錄 SRAM／外部記憶體的請求、地址、bytes、讀寫、引擎、query ID、環境版本。記憶體模型依實際讀取粒度／容量／介面轉成外部交易；不能把 C++ 陣列存取次數當作 Flash 實體交易。

指標包含峰值 SRAM（含排序暫存、padding、雙緩衝、佇列與 RRT 樹）、外部交易／bytes、hash probe 分布、掃描格／點數、AABB 剔除率、距離運算數、記憶體等待 cycles、引擎使用率、端到端 cycles 與持續吞吐量。

能量可用各操作次數乘對應技術的每次能量相加，並納入執行期間的靜態能量；沒有器件或合成依據時，只報操作與流量，不虛構功率。CPU 的執行時間／耗能只能代表 CPU 實作，不能當晶片數值。面積、頻率與功率需後續 RTL 合成或有來源的模型估算。

先讀 `examples/panda_box_0001/` 跑通格式，再測 bookshelf_thin 與 cage。這三筆尚未經 VAMP 起終點碰撞檢查，不應預設為有效問題。完整測試採全部 700 組，依既定規則標記初始有效性與失敗原因；真實感測器與深度影像測試另行加入。
