# 正確性優先驗證更新

> 歷史助理修改版報告。使用者已要求撤回額外策略，本文的 Q13 邊界案例、8,066 筆零漏判與覆蓋模型不適用於現在的代表點原方案。請看 [原方案還原紀錄](原方案還原說明.md)。

依目前優先順序，速度、耗電與硬體效益先不作為驗收門檻。規劃成功率與正確率分開報告：沒有找到路徑不自動算程式錯誤；輸出實際碰撞的路徑卻回報成功，則是正確性失敗。

## 驗收準則

| 項目 | 要求與目前判讀 |
|---|---|
| 整數規格一致性 | 量化、Morton、濾波、目錄、FK、NN 與事件須符合明確規格 |
| 碰撞漏判 | 原始點雲有碰撞而回報無碰撞，必須抓出；本次原始點雲測試要求 0 筆 |
| 額外阻擋 | 原始點雲無碰撞而保守模型判定有碰撞，另列數量；不能宣稱逐次結果完全一致 |
| 成功路徑 | 端點、關節限制、環境、自碰撞及連續運動邊全部經獨立檢查 |
| 失敗與未知 | 預算耗盡、容量不足、保守拒絕與內部錯誤分開，不把未知當作無碰撞 |
| 模組協作 | 不遺失或重複回覆、不覆寫被使用的版本、不在查詢尚未完成時提早結案 |

## 本次修正的實際漏判

先前測試著重在「整數查詢對整數參考」一致，漏掉了浮點球心進入 host adapter 時的誤差。新測試直接對每個原始 binary32 點，用 float64 暴力距離作參考，找到了反例。

原始點三軸皆約 0.000122070189 m，查詢球心三軸皆約 0.003112793091 m，查詢半徑 0.002685546875 m，加上既定點半徑 0.0025 m 後，實際有約 5.46 µm 的重疊。舊入口卻回報無碰撞。

原因是點座標的保護範圍沒有包含「查詢球心」自身的量化位移。球心每軸最近捨入最多移動 0.5 個 Q13 單位，三維距離最多 sqrt(3)/2 個單位；因此浮點球心未恰好在 Q13 網格時，查詢半徑額外加入 1 個 Q13 單位。scalar 與 batch 一起修正。若加上保護後超過 v1 半徑範圍，明確拒絕，不截斷數值。

直接傳入整數 codes 的查詢語意保持原規格；原生 C++ 規劃核心不經過這個浮點查詢入口，未改動其 FK 或路徑演算法。這次修正不能解釋先前 700 組中大量被保守覆蓋阻擋的問題。

## 實際驗證結果

- 20 項模組測試及 7 項整合測試通過，共 27 項。新增浮點球心漏判反例，以及已知不安全路徑必須被獨立幾何檢查拒絕的測試。
- 原始點雲直接比對共 8,066 筆，涵蓋正負對角近接、隨機點雲、近相切及 scalar/batch 一致性：漏判 0 筆，額外阻擋 453 筆。
- 刻意關掉 raw coverage 的雙點對照仍會漏判，驗證參考確實能抓出代表點濾波的資訊遺失。預設保守覆蓋版本有抓到此碰撞。
- 五個端到端案例已重新執行；兩條合成成功路徑通過獨立檢查。原有六條 MBM 成功路徑另重新認證，共八條成功路徑通過；已知碰撞反例被拒絕。

原始點雲測試停用徑向剔除，讓所有輸入點都在比較範圍。這是有限測試集，不是對任意感測器資料或未取樣實體幾何的完整證明。453 筆額外阻擋仍保留，表示目前碰撞結果尚未逐次等同原始點雲；不能把它們隱藏成「完全正確」。

本次沒有重新規劃全部 700 組：修改位於浮點 query adapter，原生規劃核心 SHA-256 與先前 700 組的執行紀錄一致；另重驗六條已保存的 MBM 成功路徑。先前 6/700 的數字仍是那次固定預算下的成功率，不能解讀成只有 0.86% 的計算正確。

## 現在仍有的問題

代表點版本仍有幾何漏判反例，不能用它宣稱原始場景安全。保守版本在本次測試未發現漏判，但仍有額外阻擋；若要求每次碰撞結果與原始幾何完全一致，目前尚未達標。

後續正確性工作應優先處理濾波覆蓋與精確複查，對同一筆輸入同時列出原始點雲、保守點模型與解析實體場景的答案。降低額外阻擋時仍須維持漏判檢查，不能為了提高成功率直接移除誤差保護。
