# 原方案數值與介面

設定版本 user_morton_restored_v1，對照 `docs/source/user_hackmd_original.md`，入口 `spec/design_v1.json`。

| 項目 | 本次格式 |
|---|---|
| 輸入點雲 | 世界座標 binary32 Nx3，m |
| fp32 轉換 | 依筆記 6.2.4，位元解碼及移位後取負，向零截斷為 Q14 |
| 有效 workspace | 世界座標 [-2,2)^3；偏移後每軸 unsigned16 |
| 細格 | 512 Q14 單位，即 3.125 cm，每軸 128 格 |
| 粗格 | 2048 Q14 單位，即 12.5 cm，每軸 32 格 |
| 中心點選擇 | S=4，取 q[8:5]，分數為三軸 (2o+1-16)^2 之和 |
| Morton | fine 21 bits，coarse=fine >> 6；嚴格小於才更新、平手保留先到 |
| 查詢 | 依實際半徑列舉粗格，再做 AABB 剔除及球對代表點距離 |
| 量化誤差 | 點轉換 ceil(sqrt(3))=2 LSB；浮點球心轉換另保留最多 2 LSB；FK 路徑按推導 δ_FK=1 LSB |
| 代表點以外的原始點 | 不保存、不建立 bbox、不加 voxel 覆蓋球 |
| 邊驗證 | rake 8、resolution 32，採固定 VCC validate.hh 的取樣分數與順序 |
| 規劃入口 | 七維 start、goal，rad；host 轉 Q24，現有 FK 內部旋轉 Q30 |
| 模型版本 | 各回覆帶 request ID 與 environment version |

原生 C++ 內部先以 signed world Q14 運算；輸出點資料時加 32768，得到筆記中的 workspace-relative unsigned16。此偏移不改變距離及 voxel 歸屬。

point 檔每筆 6 bytes：uint16 x,y,z，小端序。cell 檔為目前軟體向量布局：uint32 start,count 與 signed world Q14 lo[3],hi[3]，每筆 20 bytes。cell 相對座標壓縮、SoA banking 與硬體 padding 尚未完成，不能把此 debug 布局宣稱為已實作的最終 SRAM。

snapshot 的 int64 debug 列仍為 key,x,y,z,d,source_index,numeric_point_error_units,coarse_key,index,version。其中第七欄固定為 2，僅為轉換 ε，不是包住被刪點的 coverage。

直接 `Model.query(..., codes=True)` 使用世界座標 Q14 碼；公尺入口會轉成同一數值域。`Model.build_depth` 的合成入口、Q16 內參與 Q30 外參為現有軟體介面，尚非原筆記建議的最終 Q1.15 相機旋轉實作。

`planner_status` 保留模型原始狀態。成功路徑再由獨立解析幾何檢查，失敗時總驗證標為 PATH_VALIDATION_FAILED。驗證器不參與模型的碰撞決策，不因此改寫障礙範圍。

容量、規劃預算、Q24 角度及 Q30 旋轉為已列明的軟體實作選擇。Dynamic Domain、balance 與上游 Connect 的完整對齊仍未完成；這份文件不宣稱整顆 SoC 已逐項等價於來源筆記。
