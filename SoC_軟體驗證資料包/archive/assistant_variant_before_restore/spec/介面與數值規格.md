# 軟體功能模型 v1 介面與數值規格

浮點 query 入口更新：球心未恰在 Q13 網格時，scalar 與 batch 半徑都額外加入 1 個 Q13 單位，保護球心量化誤差；若加上保護後超出 65535 單位，明確拒絕。整數 codes 與原生規劃核心語意不變。反例及驗證見 `reports/正確性優先驗證報告.md`。

本版是 Panda 單一機器人、單一規劃請求內循序運算的可執行候選規格。設定以 `design_v1.json` 為準；本文件不指定最終硬體容量、時脈或匯流排協定。

## 輸入與輸出

- 點雲：世界座標、m、連續 Nx3 binary32；檔案入口可以是 XYZ，由 host 轉成此陣列。空點雲合法，非有限值明確拒絕。量化後超出可支援範圍的值拒絕；先通過徑向剔除的遠點不進入工作空間。
- 規劃：`start[7]` 與 `goal[7]`，rad，順序為 panda_joint1 到 panda_joint7。資料集保存全部 goals；本次 runner 以第一個 goal 規劃。700 筆請求的有效性與成功率分母見執行報告。
- 深度入口：uint16 HxW、0 表示無效；內參 `[fx, fy, cx, cy]`、每公尺深度單位、world_from_camera。內參 Q16，旋轉 Q30、平移 Q13。合成測試不取代真實相機驗證。
- 輸出：status、七維路徑、request ID、environment version、操作計數與驗證結果。路徑為關節空間的分段直線；未包含馬達命令、速度與加速度。

| 原生狀態值 | 名稱 | 含意 |
|---|---|---|
| 0 | SUCCESS | 功能模型找到路徑；總驗證還須獨立檢查 |
| 1 | BUDGET_EXHAUSTED | 迭代或 state 預算耗盡，不是無解證明 |
| 2 / 3 | INVALID_START / INVALID_GOAL | 在此保守模型下不合法，不等同原始幾何一定碰撞 |
| 4 | CAPACITY_EXCEEDED | hash、樹或配置容量不足，不靜默丟資料 |
| 5 | INVALID_INPUT | 不支援的數值或設定 |
| 6 | INTERNAL_ERROR | 原生例外等內部失敗 |

runner 另有 `PATH_VALIDATION_FAILED`：原生回報 SUCCESS，但獨立檢查拒絕。這屬於正確性失敗，CLI 回傳非零。一般的無路徑狀態仍會產生 path.json，path 為空。

## 運算格式與規則

| 項目 | 格式或規則 |
|---|---|
| 點、輸出球心 | signed16，13 個小數位，單位 1/8192 m |
| 關節角、內部平移 | Q24；角度由 host 最近捨入至 int32 |
| 旋轉 | Q30；30 輪整數 CORDIC |
| 中間計算 | int64；平方距離累加 uint64；適用界見 numeric_bounds.json |
| 點 ingress | 解碼 IEEE binary32 位元，向負無限量化至 Q13 |
| 其他整數除法 | 最近捨入，正好一半向正無限 |
| 球半徑與誤差 margin | 向上取整，避免因量化縮小 |
| NN 與代表點平手 | 保留最早出現的節點或點 |

有效場景工作空間 `[-2,2)^3`。細格 0.03125 m，每軸 128 格；粗格 0.125 m，每軸 32 格。細 Morton key 21 bits，x 在每組最低位、y 次之、z 最高位；粗 key 為細 key 右移 6 bits。

中心點選擇使用細格內 S=4 子格位置，三軸距離分數和最小者勝出。hash 為開放定址、線性探測，最多使用 75% 容量。排序為 3 輪各 7 bits 的穩定 radix sort，再建立粗格連續區段與代表點 AABB。

`raw_point_coverage=false` 時，只保護代表點量化誤差。true 時，以同一 voxel 原始量化點的 bbox 對代表點最遠角距離，向上開根號，再加 2 個 Q13 單位；這個覆蓋球保護保存的點，不能證明未取樣的實體障礙完整。徑向剔除 1.6 m 的適用界與 FK 誤差另有推導，不能任意縮小。

環境查詢先做 global AABB，再掃描覆蓋查詢半徑的粗格、cell AABB，最後對代表點距離測試。實際距離半徑為 query radius + point radius + 該代表點 coverage；前層剔除使用最大 coverage。不是固定 27 鄰格。

FK 從固定球形 URDF 生成常數，球數 59；自碰撞配對由同版本 SRDF 推導。環境球加入單邊 FK margin，自碰撞對加入雙邊 margin。預設 margin 設定 0.000125 m，向上量化後實際是 0.000244140625 m。

運動邊以中點及全關節鏈運動界認證區間；無法認證時細分。達深度或 state 預算就拒絕，不能把未完成認證當作安全。獨立驗證器另用 NumPy FK、解析實體障礙與每球關節鏈的界，不呼叫待測索引。

雙樹 RRT Connect 使用全掃描平方歐氏 NN、整數開根號 steering、固定交替兩樹、xorshift32、每十次目標取樣。節點插入前完成運動邊檢查，parent 僅指向已存在的節點；回溯方向固定從 start 到 goal。v1 不開啟推測批次。

## Host 與 C ABI

日常使用 `runner/model.py` 的 Model context manager：`build`、`query`、`query_many`、`build_depth`、`fk`、`plan`、`stats`、`snapshot`、`cells`、`offsets`。未成功 build 不接受 query 或 plan。批次查詢先檢查尺寸、有限值與範圍。

原生 C ABI 在 `soc_model/core.cpp` 的 `API` 函式，ctypes 宣告在 model.py 的 signatures。原生指標、陣列長度與 handle 的生命週期由 adapter 負責；這不是可以接受任意不可信指標的外部 RPC 協定。

snapshot 每點 10 個 int64：`fine_key,x,y,z,selector_score,source_index,coverage,coarse_key,sorted_index,version`。cells 每格 9 個 int64：`coarse_key,start,count,lo_xyz,hi_xyz`。這是 debug 格式；實際 packed 測試向量格式另見 `environment_snapshot/layout.json` 與 `rtl_vectors/v1/manifest.json`。

trace 每列 8 個 int64：`kind,id,version,address,read_bytes,write_bytes,units,result`。主要 kind：1 建構、2 FK、3 query、4 NN、5 edge、6 sample、7 insert、8 Connect、9 plan、10 memory。30/31 為 state 組態、32/33 為新節點組態、34/35 為 NN target、38/39 為樹根組態；每對紀錄分開保存七個角度碼。節點 ID 為 `(tree << 32) | index`。

trace buffer 可限長，但 dropped 必須保留。缺資料的結構 replay 回報 INCOMPLETE_TRACE；時間模型不能把截斷 trace 當完整工作。live callback 即使 trace 儲存到上限仍接收全部實際事件。

## 環境版本與事件

EnvironmentManager 有兩個 slots。prepare 在未使用或未 pin 的 slot 建構；成功後才允許 publish。每個 query/plan pin 自己版本，回覆帶原 request ID 與 version。取消會先回覆 CANCELLED，但實體 pin 等原操作 drain 後才釋放。容量不足或 failed build 不更新 active environment。

多筆 query 可以有不同延遲並亂序完成；重複完成、覆寫 pin 中的 slot 與倒退時間均被拒絕。此事件模型驗證控制語意，未模擬處理器、作業系統、中斷或 AXI 訊號。

## 時間、資源與能量的範圍

執行時由原生實際事件逐筆推進 OnlineTiming。v1 採單一路徑相依的循序排程，建構與 DMA 先用操作計數註記，query 階段支援 SRAM bank 與 LRU cache / 外部交易。設定變更不得改變功能路徑，整合測試會比對 live、replay 及無時間註記結果。

SRAM 計數為候選 packed 配置：hash 32 B/slot、環境雙緩衝、dense IDs、offsets、20 B/cell、8 B/point、排序暫存與雙樹 36 B/node。它不是 C++ process RSS，也未宣稱最終 RTL 的實體 SRAM 宏、額外 FIFO 與對齊成本已定案。

能量為可替換係數的操作量模型，包含簡化整數操作、已計數的邏輯 SRAM bytes、外部 bytes 與靜態係數。所有係數目前 null，回報 UNCHARACTERIZED。尚未包含經校正的控制、時脈網路與實體互連成本。多引擎並行、跨 frame 重疊吞吐量、器件功耗與面積需要後續設計及校正，現有串行估計不可當作它們的量測值。
